## 0. エグゼクティブサマリー

ブラウザ上で **Excel VBA を「読む → 書く → 動かす → 理解する」** を一気通貫で学べる学習ソフトを企画する。
最大の論点は **「VBAの実ランタイム（Office/Excel）はブラウザで動かない」** こと。本企画では、これを正面から扱い、
**段階的な3層の実行戦略（疑似インタプリタ → 解説付きトレース → 実Excel課題）** で解決する。

既存の `ai-tools-navi` は Next.js 16 / App Router / 静的中心 / SEO・アフィリエイト型サイト。
本ソフトは **同リポジトリ内の `/learn/vba` セクション** として実装し、既存のSEO資産・デザイン・収益導線を再利用するのが最もコスト効率が高い。

**提供形態は「ログイン形式のWeb学習サイト」**（アカウントに進捗をクラウド保存し、PC↔スマホで同期・「続きから」再開・修了証を発行）。
ただしレッスンの閲覧・実行は未ログインでも可能な**公開/会員ハイブリッド**とし、検索流入と会員登録の動機づけを両立する（詳細は §5.1・§6）。

## 1. 背景と目的

### 1.1 なぜVBAか
- Excel VBA は日本の事務・経理・情報システム部門で依然として需要が高い（求人・書籍ともに底堅い）。
- 一方で学習リソースは「書籍」か「動画」が中心で、**ブラウザで手を動かして即フィードバック**を得られる教材は少ない。
- 既存サイト読者層（AIツール・業務効率化に関心がある層）と **「Excel自動化を学びたい層」は高い親和性** がある。

### 1.2 ゴール
- 非エンジニアの事務職が、**マクロの記録だけに頼らず、自分でVBAを書けるようになる**こと。
- 「写経して終わり」ではなく、**実行結果を観察しながら概念を理解**できること。

### 1.3 非ゴール（スコープ外）
- VBAの完全な処理系の再実装（Officeオブジェクトモデル全体の再現はしない）。
- Word/PowerPoint/Access VBA（初版はExcel VBAに限定）。
- ネイティブアプリ / デスクトップアプリ化（初版はWebのみ）。

## 3. 学習設計（カリキュラム）

### 3.1 学習モデル
各レッスンは **「概念 → 例（トレース実行）→ 穴埋め/修正課題 → 自由演習 → ミニクイズ」** の5ステップで統一する。

### 3.2 カリキュラム構成（初版：全7章・約40レッスン想定）

1. **はじめてのVBA** — VBEの開き方、マクロとは、Sub/End Sub、`MsgBox`
2. **変数とデータ型** — `Dim`、String/Long/Double/Boolean、代入、`Option Explicit`
3. **セルを操作する** — `Range` / `Cells`、`.Value`、`.Offset`、選択と書き込み
4. **条件分岐** — `If...Then...Else`、比較演算子、`Select Case`
5. **繰り返し** — `For...Next`、`For Each`、`Do While/Until`、最終行取得
6. **手続きと部品化** — `Sub` / `Function`、引数、戻り値、スコープ
7. **実務パターン集** — 重複削除・転記・集計・シート横断・簡易エラー処理（`On Error`）

> 拡張章（v2以降）: 配列とコレクション / イベントプロシージャ / ユーザーフォーム / 外部ファイル操作 / API的処理。

### 3.3 各レッスンのメタデータ（データモデル）
```ts
interface Lesson {
  slug: string;            // "variables-and-types"
  chapter: number;
  order: number;
  title: string;
  goal: string;            // このレッスンで「できるようになる」こと
  concept: string;         // Markdown解説
  example: VbaSnippet;     // トレース実行つきサンプル
  exercises: Exercise[];   // 穴埋め・修正・自由演習
  quiz: QuizItem[];
  estMinutes: number;
}
```

## 4. 技術的核心：「VBAをどう動かすか」

ブラウザでは実VBA（COM/Office）は動作しない。これを **3層の実行戦略** で段階的に解決する。

### 4.1 戦略A：疑似VBAインタプリタ（MVPの中核）
- VBAの **サブセット** をJS/TSで解釈する小さなインタプリタを自作する。
- 対応範囲（初版）: `Sub/Function`、`Dim`/型、代入、四則・比較・論理演算、`If/Select Case`、
  `For/For Each/Do`、`MsgBox`/`Debug.Print`、文字列関数（`Len`,`Left`,`Mid`,`UCase`等）、
  そして **仮想ワークシート上の `Range`/`Cells`/`.Value`/`.Offset`**。
- UIに **仮想スプレッドシート（グリッド）** を持ち、コードがセルを書き換える様子を可視化する。
- 実装方式: トークナイザ → パーサ → AST → ステップ実行可能なインタプリタ（ジェネレータで1ステップずつ`yield`）。
- メリット: ネットワーク不要・即フィードバック・**ステップ実行/変数ウォッチ/セルのハイライト**が作れる。
- 制約: Officeオブジェクトモデル全体は再現しない → 「対応済み構文一覧」を明示し、未対応は親切なエラーで案内。

### 4.2 戦略B：解説付きトレース（インタプリタ未対応の高度な例）
- 実行できない高度なコードは、**事前に用意した実行ログ/状態スナップショット** を1行ずつ再生する“録画再生”方式で見せる。
- 著者が用意した「期待される状態遷移」を表示するため、**正確性を担保**しつつ表現力を確保。

### 4.3 戦略C：実Excelで動かす課題（学習の出口）
- ダウンロード可能な `.xlsm` 演習ブック / コピペ用 `.bas` を配布。
- 「VBEに貼り付けて F5 で実行 → 結果を確認」までを **手順つきで案内**。
- ブラウザ学習と実務をつなぐ“最後の一歩”を担保する。

### 4.4 採用方針
- **MVPは戦略A中心**（最重要・差別化要因）。Bは補助、Cは各章末に配置。
- インタプリタは独立パッケージ `lib/vba-engine/` として副作用なしに実装し、**ユニットテスト可能**にする。

> 検討した代替案: ①WebAssembly化されたBASIC処理系の流用 → VBA構文/Office依存と乖離が大きく不採用。
> ②サーバ上でLibreOffice headlessを叩く → コスト・レイテンシ・セキュリティ（任意コード実行）で初版は不採用（将来オプション）。

## 6. データ・進捗管理（ログイン形式の会員サイト）

> 方針転換: 本ソフトは **ログイン形式のWeb学習サイト** として構築する。進捗・回答・修了状況を
> アカウントに紐づけてクラウド保存し、PC↔スマホ間で同期・「続きから」再開できるようにする。

### 6.1 認証（ログイン）
- **認証方式**: ソーシャルログイン（Google / GitHub 等）＋メールリンク（マジックリンク）を推奨。
  パスワード管理の負担・漏洩リスクを避けられ、事務職ターゲットにも登録ハードルが低い。
- **実装の選択肢**（いずれもVercel/サーバレスと相性良）:
  - **Auth.js（NextAuth v5）**: Next.js App Routerネイティブ。無料・自前運用。DBは別途用意。
  - **Clerk**: UI・メール・セッション込みで最速。無料枠あり、月間アクティブ数で課金。
  - **Supabase Auth**: 後述DBと一体運用でき、認証＋DBを1つのサービスに集約可能。
  - → **初期はClerkかSupabase Authで開発速度を優先**、コスト最適化が必要になればAuth.jsへ移行、が現実的。
- **セッション保護**: `/mypage` や `/api/progress` はミドルウェア/サーバ側でセッション検証。未ログインは `/login` へ誘導。

### 6.2 データストア
- **DB**: サーバレスPostgres（**Neon / Supabase / Vercel Postgres**）を推奨。Vercelデプロイと親和性が高い。
- **主なテーブル**:
  ```
  users          … 認証プロバイダのユーザーID・表示名・作成日（認証サービスが持つ場合は最小限）
  progress       … user_id, lesson_slug, status(未着手/進行中/完了), score, updated_at
  submissions    … user_id, exercise_id, submitted_code, is_correct, created_at（学習履歴・復習用）
  certificates   … user_id, scope(章/コース), issued_at
  ```
- **コンテンツ本体**は従来どおり **TS/MDX の静的ファイル**（`content/vba/*`）で管理し、DBは「ユーザー固有の状態」だけを持つ。コンテンツとユーザーデータを分離することで、DB肥大とコストを抑える。

### 6.3 進捗の保存フロー
- レッスン完了・演習採点のたびに `/api/progress`（要ログイン）へ保存。
- **未ログインで学習を始めた場合**: localStorage に一時保存 →ログイン時にサーバへ**マージ**（体験の連続性を担保）。
- 採点自体はクライアントの疑似インタプリタで完結し、結果（正誤・スコア）だけをサーバに記録。

### 6.4 プライバシー・法令
- 個人情報（メール等）取得のため、既存サイトの `privacy` ページに準拠し**利用目的・保存内容・削除方法**を明記。
- **退会・データ削除**の導線をマイページに用意（GDPR/個人情報保護法対応の基本）。

## 10. リスクと対策

| リスク | 影響 | 対策 |
|---|---|---|
| 疑似インタプリタの非対応構文に学習者が混乱 | 学習体験低下 | 「対応構文一覧」明示＋親切なエラー＋未対応は戦略B/Cへ誘導 |
| 採点の誤判定 | 信頼失墜 | エンジンのユニットテスト網羅、期待出力ベースの採点、著者レビュー |
| Next.js 16の破壊的変更（AGENTS.md警告） | 実装手戻り | 着手前に同梱docsを必読、最小構成で素振り |
| スコープ肥大（Office全再現の誘惑） | 納期遅延 | サブセットを契約として固定、未対応は明文化 |
| コンテンツ作成コスト | リリース遅延 | レッスン雛形を定型化（5ステップ）し量産可能に |
| 個人情報の管理・漏洩 | 信頼失墜・法令違反 | 認証はマネージドサービス活用、DBに機微情報を持たない、退会/削除導線、privacy整備 |
| 認証・DBの月額コスト | 運用負担 | 無料枠の大きいサービスで開始、会員数に応じ段階的に有料化 |
